# Подготовка сайта и PDF

Исходный текст кейса: [case-storeassist.md](../case-storeassist.md). Схемы используются из `assets/diagrams/` без перестройки. Обложка и страница кейса сохраняют цвета StoreAssist.

Из корня проекта:

```text
python -m pip install -r scripts/requirements-publication.txt
python scripts/build-publication.py
python scripts/validate-publication.py
python -m http.server 8819 --bind 127.0.0.1 --directory pages-build
```

Сборка создаёт `output/pdf/case-storeassist.pdf` и отдельный каталог `pages-build/`. Каталог назначения должен быть новым: сборка не удаляет существующие файлы. Для следующего прогона передайте `--output` с другим именем.

Сайт содержит кейс, прототип, документы с исходными якорями, восемь схем и редактируемые исходники. PDF содержит краткую историю, решения, метрики и все восемь готовых схем на отдельных страницах исходного масштаба; для деталей используется увеличение.

Краткий текст PDF и страницы кейса находится в сборщике; при редактуре единого кейса эти версии нужно сверять. Рабочая карта покрытия остаётся источником статуса приёмки. Новые скриншоты до проверки отрисовки не добавлены.

На Windows используются Segoe UI; в Linux требуется DejaVu Sans. Тесты прототипа запускаются отдельно из `prototype/` командой `npm test` (Node.js 24).

PDF и ссылки проверяются при подготовке. Это не заменяет проверку сайта в браузере, прототипа на устройствах и реальной серверной авторизации. Измеренных результатов пилота нет.
