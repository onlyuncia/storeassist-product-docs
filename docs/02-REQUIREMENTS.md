# Требования и бизнес-правила

Требования описывают целевое решение StoreAssist и связаны с [процессом TO-BE](01-PROCESS-AS-IS-TO-BE.md). Сохраняются iPod продавца и терминал на складе. Как и в AS-IS, фактическую передачу подтверждает сотрудник склада на терминале.

## Термины

| Термин | Значение |
| --- | --- |
| Запрос со склада | Поиск и выдача одной единицы точного варианта товара |
| Обслуживание | Связанные запросы одного покупателя под ответственностью продавца |
| Обращение на проверку | Отдельная задача по расхождению наличия или размещения, которую ведёт старший склада |
| Передача поиска | Смена складского исполнителя по одному запросу после принятия коллегой |
| Передача обслуживания | Смена продавца для всего обслуживания после принятия коллегой |

| RULE-03 | <a id="rule-03"></a>Наличие в учёте не является резервированием; модуль не вводит жёсткий резерв | Просмотр наличия и создание запроса не образуют жёсткого резерва. | [BG-01](#bg-01), [BG-05](#bg-05) |
| RULE-04 | <a id="rule-04"></a>Повторная отправка одного действия не создаёт второй запрос; отдельные намеренные запросы на одинаковый товар допустимы | Повтор одной отправки даёт один результат; отдельный намеренный запрос на тот же вариант разрешён. | [BG-01](#bg-01), [BG-05](#bg-05) |
| RULE-05 | <a id="rule-05"></a>Другой размер, цвет или товар не подменяют исходный запрос | Найденный другой размер / цвет не завершает исходный запрос как переданный. | [BG-01](#bg-01), [BG-05](#bg-05) |
| RULE-06 | <a id="rule-06"></a>«Передан» устанавливается после подтверждения сотрудником склада фактической передачи товара продавцу на складском терминале | Готовность и уведомление не закрывают выдачу; финальный исход возникает после сохранённого подтверждения склада. | [BG-01](#bg-01) |
| RULE-07 | <a id="rule-07"></a>«Не найдено» завершает конкретный поиск и не меняет учётный остаток автоматически. | RULE-08 | <a id="rule-08"></a>Отмена начатого запроса требует подтверждения исполнителя | Начатая отмена не становится финальной до подтверждения исполнителем. | [BG-03](#bg-03) |
| RULE-09 | <a id="rule-09"></a>История состояний, исполнителей, предусмотренных правилами причин и добавленных комментариев сохраняется; завершённый исход не переписывается | Новые события не переписывают старые состояния, авторов, причины и добавленные комментарии. | [Процесс](01-PROCESS-AS-IS-TO-BE.md) |
| RULE-10 | <a id="rule-10"></a>Номер телефона, имя и иные персональные данные покупателя для запроса не нужны | Создание запроса не требует имени, телефона и других персональных данных покупателя. | [BG-06](#bg-06) |

При неизвестном или устаревшем наличии требуется отдельное подтверждение продавца после предупреждения; если актуальность не подтверждена, применяется эта же ветка. Принятие запроса не гарантирует физическое наличие | При актуальном нуле запрос не создаётся. Результат относится к этой попытке: положительное значение допускает отправку, ноль запрещает её; ошибка, отсутствие значения или неподтверждённая актуальность требуют предупреждения по [RULE-21](#rule-21). При неудаче старый ноль считается неподтверждённым, а полученный при успешном обновлении ноль блокирует запрос. Успешное чтение учётного остатка само по себе не означает, что вещь физически найдена. | [BG-01](#bg-01), [BG-05](#bg-05), [RULE-03](#rule-03), [RULE-21](#rule-21) |

## Функциональные требования

### Создание запроса и очередь

| ID | Требование | Проверяемый результат | Связи |
| --- | --- | --- | --- |
| FR-01 | <a id="fr-01"></a>Продавец видит выбранный вариант, полученное из существующей системы наличие и доступную информацию о времени его обновления. Неизвестные и устаревшие сведения, неподтверждённая актуальность и недоступность источника обозначены явно | Видны вариант, значение из источника и доступное время обновления. Актуальный ноль отличим от неизвестного наличия и устаревшего значения, включая прежний ноль. | [BG-01](#bg-01), [RULE-03](#rule-03), [RULE-21](#rule-21) |
| FR-02 | <a id="fr-02"></a>Перед отправкой продавец проверяет товар, размер, цвет и место передачи; остаток обновляется по [FR-32](#fr-32) и применяется проверка наличия [FR-31](#fr-31). После принятия получает номер и время запроса. Неопределённая отправка отображается отдельно от принятого запроса | После принятой отправки показаны номер, вариант, место и сохранённое время. При неизвестном результате отправка не объявлена успешной. | [BG-01](#bg-01), [RULE-01](#rule-01), [RULE-21](#rule-21), [FR-31](#fr-31), [FR-32](#fr-32) |
| FR-03 | <a id="fr-03"></a>Рабочее место склада показывает актуальные запросы своего магазина, их возраст, состояние и стеллаж / секцию из существующей системы. При отсутствии адреса это явно указано. По умолчанию новые запросы упорядочены по времени создания. Отображение и обновление размещения выполняются по [FR-34](#fr-34) | В очереди видны возраст, состояние и стеллаж / секция либо отсутствие адреса. Ожидающие запросы упорядочены по времени создания. | [BG-01](#bg-01), [RULE-28](#rule-28), [FR-34](#fr-34) |
| FR-04 | <a id="fr-04"></a>Принятие в работу фиксирует исполнителя и время. При одновременном принятии второй сотрудник видит актуального исполнителя | При двух одновременных принятиях сохранён один исполнитель; второй получает актуальное назначение. | [RULE-02](#rule-02) |
| FR-05 | <a id="fr-05"></a>Текущий ответственный продавец видит ход запросов своего обслуживания и признак запрошенной отмены | Текущий продавец видит состояния всех запросов своего обслуживания и ожидающую отмену. | [BG-01](#bg-01), [BG-03](#bg-03), [RULE-19](#rule-19) |

### Выдача, исход поиска и отмена

| ID | Требование | Проверяемый результат | Связи |
| --- | --- | --- | --- |
| FR-06 | <a id="fr-06"></a>Исполнитель отмечает готовность после подбора нужного варианта, с сохранением места передачи | После подбора правильного варианта показано «Готов к передаче» с местом выдачи; финальная передача ещё не подтверждена. | [BG-01](#bg-01), [RULE-05](#rule-05) |
| FR-07 | <a id="fr-07"></a>Сотрудник склада подтверждает фактическую передачу нужного варианта продавцу на складском терминале. После сохранения запрос получает состояние «Передан», видимое продавцу в iPod. Отметка готовности сама не завершает выдачу | Сохранённое подтверждение склада завершает запрос как «Передан» и видно в iPod без дополнительного подтверждения продавцом. | [RULE-06](#rule-06) |
| FR-08 | <a id="fr-08"></a>Исполнитель фиксирует «Не найдено» на складском терминале и при желании добавляет свободный комментарий. Выбор причины не требуется; пустой комментарий не блокирует сохранение. Сохраняются исполнитель, время и комментарий, если он добавлен. При доступной связи исход и добавленный комментарий видны в запросе на iPod продавца; продавец получает уведомление без личного сообщения в зале | Пустой и заполненный комментарий допускаются без выбора причины. Сохранены исполнитель и время; при доступной связи продавец получает уведомление, а добавленный комментарий виден в запросе. | [BG-02](#bg-02), [RULE-07](#rule-07) |
| FR-09 | <a id="fr-09"></a>Продавец отменяет непринятый запрос или направляет отмену исполнителю начатого запроса. Причина обязательна | Непринятый запрос отменяется с причиной. Начатый остаётся активным с признаком отмены до ответа исполнителя. | [BG-03](#bg-03), [RULE-08](#rule-08) |
| FR-10 | <a id="fr-10"></a>Исполнитель подтверждает отмену начатого запроса на складском терминале после урегулирования фактического движения вещи. При споре руководитель помогает сверить факты с текущим продавцом и исполнителем по [RULE-27](#rule-27). Если нужный вариант уже передан, исполнитель подтверждает передачу по [FR-07](#fr-07); если не передан и положение вещи урегулировано — отмену. До выяснения запрос остаётся активным с ожидающей отменой. Перед фиксацией проверяются актуальный исполнитель и состояние; завершённый исход не переписывается. При неизвестном результате сохранения действует [FR-16](#fr-16) | Фактический исход сохраняет текущий складской исполнитель; роль руководителя не разрешает завершать запрос вместо него. В истории остаются причина отмены, участие руководителя, итог сверки, автор и время. Неустановленный факт не становится подтверждённой отменой или передачей, назначение и время создания сохраняются. Дополнительное подтверждение продавца не требуется. | [BG-03](#bg-03), [RULE-06](#rule-06), [RULE-08](#rule-08), [RULE-09](#rule-09), [RULE-27](#rule-27), [FR-07](#fr-07), [FR-12](#fr-12), [FR-16](#fr-16) |

### История, доступ и исключения

| ID | Требование | Проверяемый результат | Связи |
| --- | --- | --- | --- |
| FR-11 | <a id="fr-11"></a>Повторная попытка отправки сохраняет один результат исходного действия; после восстановления связи отображается актуальное состояние | Повтор одного действия не создаёт дубля; после восстановления связи показан сохранённый результат. | [RULE-04](#rule-04) |
| FR-12 | <a id="fr-12"></a>История показывает создание, принятие, передачу поиска и обслуживания, готовность, выдачу, отмену и финальный исход с реальными участниками и временем; видны ссылки на обращения и альтернативы. Смена ответственного не переписывает авторов прежних событий. При отправке с неподтверждённым наличием история сохраняет предупреждение и подтверждение продавца с участником и временем | Доступны события с авторами и временем, передачи работы и связи с обращениями / альтернативами. Смена ответственного не меняет прежних авторов. При отправке с неподтверждённым наличием доступны предупреждение, подтверждение продавца и время. | [RULE-09](#rule-09), [RULE-13](#rule-13), [RULE-14](#rule-14), [RULE-16](#rule-16), [RULE-19](#rule-19), [RULE-21](#rule-21) |
| FR-13 | <a id="fr-13"></a>В приложении видны новые исходы и изменения собственных запросов. Прочтение уведомления или отсутствие реакции на него не изменяет состояние запроса; передачу подтверждает сотрудник склада | Продавец видит изменения своего обслуживания. Чтение уведомления и отсутствие реакции не изменяют состояние запроса. | [BG-01](#bg-01), [RULE-06](#rule-06) |
| FR-14 | <a id="fr-14"></a>Для первого пилота система при достижении 5 минут от сохранённого времени создания активного запроса показывает продавцу и руководителю смены визуальную пометку с текстом и текущим временем ожидания. Пометка применяется к состояниям «Создан», «В работе» и «Готов к передаче», включая ожидающую отмену. Смена состояния или ответственного не сбрасывает возраст; после финального исхода активная пометка не показывается. Автоматической смены исполнителя или завершения нет; передачу поиска можно предложить при выполнении [RULE-12](#rule-12) | До 5 минут пометки нет, при достижении порога она видна у активного запроса. Состояние, исполнитель и время создания сохраняются. После передачи поиска или обслуживания возраст продолжается; для финального запроса пометки активного ожидания нет. | [BG-01](#bg-01), [RULE-12](#rule-12), [RULE-13](#rule-13), [RULE-18](#rule-18), [RULE-22](#rule-22) |
| FR-15 | <a id="fr-15"></a>Данные доступны только сотрудникам своего магазина. Продавец управляет обслуживанием по текущему назначению, включая принятые от коллеги запросы, и видит сводку предыдущих поисков без открытия чужого обслуживания. Предложенная передача даёт только просмотр контекста для решения. Склад видит свою очередь; руководитель — запросы смены; старший склада — новые обращения своего магазина и проверки, которые он принял; итог и закрытие доступны ответственному старшему по [RULE-24](#rule-24) | Чужой магазин недоступен. Управление разрешено текущему продавцу; получатель предложения до принятия видит только контекст, сводка прошлого поиска не открывает чужое обслуживание. Новые обращения доступны старшему своего магазина, принятие фиксирует ответственного; завершение проверки требует его полномочий. | [RULE-10](#rule-10), [RULE-11](#rule-11), [RULE-14](#rule-14), [RULE-17](#rule-17), [RULE-19](#rule-19), [RULE-24](#rule-24) |
| FR-16 | <a id="fr-16"></a>При потере связи неизвестный результат явно показан. Принятие, отмена, выдача, смена складского исполнителя или продавца, создание обращения или альтернативного запроса не объявляются успешными без сохранённого результата; повтор исходного действия не создаёт дубль | При потерянном ответе показан неизвестный результат до сверки; повтор исходного действия не создаёт вторую запись или смену ответственного. | [BG-01](#bg-01), [RULE-04](#rule-04) |
| FR-17 | <a id="fr-17"></a>Если после отметки готовности обнаружена ошибка варианта или вещь фактически недоступна, исполнитель возвращает запрос в работу с причиной. Повторный поиск и итог сохраняются в истории; запрошенная отмена не теряется | Возврат в работу сохраняет причину, историю готовности и признак ожидающей отмены; ошибочная готовность не становится выдачей. | [RULE-05](#rule-05), [RULE-09](#rule-09) |

### Предыдущий поиск и передача коллеге

| ID | Требование | Проверяемый результат | Связи |
| --- | --- | --- | --- |
| FR-18 | <a id="fr-18"></a>Перед созданием и принятием запроса система заново оценивает предупреждение по магазину и точному варианту: оно показывается, если от сохранённого исхода «Не найдено» прошло менее 2 часов и проблема не снята последующим подтверждённым результатом. В сводке видны время, проверенное место, исход и результат проверки. Просмотр не продлевает срок; новый исход начинает своё окно. Истёкшие и уточнённые сведения остаются в истории. При выполнении [FR-31](#fr-31) продавец может продолжить запрос | В 1 ч 59 мин 59 с предупреждение ещё показывается, если проблема не снята; с 2 ч и после досрочного снятия — нет. История остаётся доступна. Предупреждение само по себе не запрещает отправку и не отменяет правило наличия. | [BG-04](#bg-04), [RULE-11](#rule-11), [FR-31](#fr-31) |
| FR-19 | <a id="fr-19"></a>Текущий складской исполнитель или руководитель вручную выбирает другого сотрудника со складским полномочием своего магазина и предлагает ему передачу поиска. Получатель принимает либо отклоняет предложение. При предложении и принятии проверяются полномочия инициатора / получателя, магазин, состояние, ожидающая отмена и актуальный исполнитель; смена сохраняется целиком без двух исполнителей | Доступен ручной выбор другого сотрудника склада своего магазина. После сохранённого принятия выбранным получателем назначен один новый исполнитель. Недопустимый инициатор, чужой магазин, отсутствие складского полномочия, выбор текущего исполнителя, недопустимое состояние, ожидающая отмена или устаревшее назначение не приводят к смене. | [BG-01](#bg-01), [RULE-12](#rule-12), [RULE-13](#rule-13) |
| FR-20 | <a id="fr-20"></a>При передаче поиска сохраняются проверенные места, пояснение и попытки с участниками и временем. Первый момент принятия и возраст запроса не сбрасываются; отказ и отсутствие ответа оставляют прежнего исполнителя | Новый исполнитель получает проверенные места и попытки; первоначальное время и возраст сохранены. При отказе или отсутствии ответа остаётся прежний исполнитель. | [BG-01](#bg-01), [RULE-13](#rule-13) |

### Проверка расхождений и размещения

| ID | Требование | Проверяемый результат | Связи |
| --- | --- | --- | --- |
| FR-21 | <a id="fr-21"></a>Из «Не найдено» либо сообщения о другом месте хранения можно создать связанное обращение с типом проблемы, магазином и вариантом. При существующем открытом обращении того же магазина и варианта эпизод добавляется к нему; повтор одного действия не создаёт дубль. Новое обращение доступно старшему склада своего магазина для принятия; добавление эпизода в существующее не меняет его ответственного | Эпизод связан с обращением своего магазина и варианта; открытое обращение дополняется, повтор одного действия не создаёт дубля. Новое обращение поступает старшему своего магазина; назначение существующего обращения сохраняется. | [BG-04](#bg-04), [RULE-14](#rule-14), [RULE-24](#rule-24) |
| FR-22 | <a id="fr-22"></a>Старший склада принимает обращение своего магазина; сохраняются конкретный ответственный и время принятия. Он проводит или организует проверку, фиксирует результат, пояснение и время, затем закрывает завершённую проверку. Закрытие без результата недоступно, незаконченная проверка остаётся в работе. Учётное исправление выполняет уполномоченный сотрудник в действующей системе; если операция выполнена, старший сохраняет её ссылку или отметку. Старший может исправить учёт сам только при отдельном полномочии. Принятие обращения не меняет исполнителя запроса выдачи. После завершения проверки размещения запускается повторное получение адреса по [FR-34](#fr-34); сбой чтения не отменяет сохранённый итог проверки | После принятия видны ответственный старший и время. Без результата закрытие недоступно. Итог и закрытие сохранены ответственным старшим; при фактической корректировке есть сведения об операции. Учёт автоматически не меняется, роль старшего не предоставляет учётных прав. | [BG-04](#bg-04), [RULE-14](#rule-14), [RULE-15](#rule-15), [RULE-24](#rule-24), [RULE-28](#rule-28), [FR-34](#fr-34) |
| FR-23 | <a id="fr-23"></a>Сотрудник сообщает исходное и фактическое место хранения найденного варианта с пояснением. Оба адреса относятся к своему магазину. Наблюдение добавляется к обращению; выдача продолжается, источник размещения автоматически не меняется | Сохранены исходное и фактическое место своего магазина; сообщение связано с обращением. Выдача продолжается, адрес источника автоматически не меняется. | [BG-04](#bg-04), [RULE-15](#rule-15) |
| FR-24 | <a id="fr-24"></a>Сводка поиска показывает результат обращения и время проверки. После подтверждённого нахождения или проверки, снявшей проблему, активное предупреждение снимается до истечения двухчасового срока, прежние сведения помечаются уточнёнными; исторический исход сохраняется. Наличие и адрес из источника показаны отдельно от наблюдений. Повторное чтение адреса и состояния его актуальности выполняется по [FR-34](#fr-34); наблюдение сотрудника не подменяет ответ источника | Результат и время проверки видны отдельно от данных источника. Подтверждённое снятие проблемы прекращает активное предупреждение раньше двух часов, сохраняя прежний исход поиска. Само снятие предупреждения не обновляет учётное наличие. | [BG-04](#bg-04), [RULE-11](#rule-11), [RULE-14](#rule-14), [RULE-15](#rule-15), [RULE-28](#rule-28), [FR-34](#fr-34) |
| FR-34 | <a id="fr-34"></a>После завершения проверки размещения и при следующем открытии карточки с размещением варианта StoreAssist заново получает стеллаж / секцию своего магазина и точного варианта из действующей системы. Показываются время получения и доступное время обновления источника. При сбое последнее успешно полученное значение сохраняется с предупреждением о неудаче обновления и неподтверждённой актуальности; если значения нет, размещение обозначено неизвестным. Явный ответ об отсутствии адреса отличается от сбоя. Наблюдение, результат проверки и сведения об учётной операции показаны отдельно; вернувшийся прежний адрес не подменяется предполагаемым новым | После обоих событий выполнено новое чтение нужного магазина / варианта. Успешный ответ, отсутствие адреса и недоступность различаются. Сбой не отменяет сохранённую проверку и не меняет историю, назначение или исход запроса выдачи. Само чтение не меняет учёт и не снимает предупреждение «Не найдено»; новый адрес считается полученным из источника только после успешного ответа с ним. | [BG-04](#bg-04), [RULE-11](#rule-11), [RULE-14](#rule-14), [RULE-15](#rule-15), [RULE-24](#rule-24), [RULE-28](#rule-28) |

Сбой источника не выдается за пустой результат. ### Обслуживание и смена продавца

| ID | Требование | Проверяемый результат | Связи |
| --- | --- | --- | --- |
| FR-27 | <a id="fr-27"></a>Первый запрос создаёт обслуживание с общим номером и ответственным продавцом; связанные запросы относятся к нему. Обслуживание не требует имени и контактов покупателя. Продавец завершает его только при финальных исходах всех запросов и отсутствии ожидающих предложений передачи | Запросы одного обслуживания имеют общий номер без персональных данных покупателя. Завершение недоступно при открытых запросах или ожидающих предложениях передачи. | [BG-06](#bg-06), [RULE-10](#rule-10), [RULE-20](#rule-20) |
| FR-28 | <a id="fr-28"></a>Продавец или руководитель предлагает коллеге своего магазина продолжить обслуживание перед перерывом, окончанием смены или при необходимости помощи более опытного продавца в сложной ситуации. Коллега принимает или отклоняет предложение. Одновременно ожидает ответа не более одного предложения по обслуживанию; смена продавца сохраняется целиком после проверки актуального назначения и активности обслуживания. Повторная попытка после отказа или отсутствия ответа выполняется по [FR-33](#fr-33) | До принятия отвечает прежний продавец; отказ не меняет назначение. Принятие коллегой своего магазина сохраняет одного ответственного и не допускает параллельного перехода. | [BG-06](#bg-06), [RULE-17](#rule-17), [RULE-20](#rule-20), [RULE-25](#rule-25), [FR-33](#fr-33) |
| FR-29 | <a id="fr-29"></a>После принятия новый продавец получает управление всем обслуживанием и уведомления о новых событиях; ему доступна сводка непросмотренных результатов. Прежний продавец теряет право изменять запросы этого обслуживания. Склад видит нового ответственного; доставленные ранее сообщения не дают права действовать по старому назначению | Новый продавец управляет всем обслуживанием, получает новые события и непросмотренные результаты; прежний больше не может изменять запросы. Склад видит текущего продавца. | [BG-06](#bg-06), [RULE-17](#rule-17), [RULE-19](#rule-19) |
| FR-30 | <a id="fr-30"></a>При передаче сохраняются товары, все связанные запросы, результаты, согласованные альтернативы, ожидающие отмены, зона передачи и история. Складские исполнители, очередь, состояния и времена не меняются. При принятии показывается актуальный контекст, включая новые события, возникшие после предложения | При смене продавца сохранены контекст, исполнители, состояния, очередь, зона, времена и отмены. Во время принятия видны актуальные исходы, повторной выдачи нет. | [BG-06](#bg-06), [RULE-18](#rule-18), [RULE-19](#rule-19) |
| FR-33 | <a id="fr-33"></a>При отказе или отсутствии ответа на передачу обслуживания текущий продавец может выбрать другого коллегу своего магазина. При затруднении или отсутствии продавца новую передачу организует руководитель. Если прежнее предложение ещё ожидает ответа, текущий продавец или руководитель сначала отзывает его; новое создаётся только после подтверждённого разрешения прежнего. Проверяются актуальный продавец, активность обслуживания и состояние предложения. При неизвестном результате отзыва сначала проводится сверка по [FR-16](#fr-16). Новый коллега сам принимает обслуживание; прежние предложения и события сохраняются | После отказа доступна новая попытка; после отсутствия ответа сначала сохранён отзыв. Одновременно ожидает ответа одно предложение; прежний продавец остаётся назначенным до нового принятия, запросы на выдачу продолжаются. Отозванное предложение принять нельзя; уже сохранённое принятие не отменяется устаревшим отзывом. Время запросов не сбрасывается, предложения учитываются отдельно. | [BG-06](#bg-06), [RULE-17](#rule-17), [RULE-18](#rule-18), [RULE-19](#rule-19), [RULE-20](#rule-20), [RULE-25](#rule-25), [FR-12](#fr-12), [FR-16](#fr-16) |

| FR-31 | <a id="fr-31"></a>После обновления остатка по [FR-32](#fr-32) перед созданием обычного или альтернативного запроса система применяет правило наличия: актуальный положительный остаток допускает обычную отправку; актуальный ноль запрещает её; неизвестные или устаревшие сведения требуют предупреждения и отдельного подтверждения продавца для выбранного варианта и текущей отправки. Если актуальность не подтверждена, сведения считаются неподтверждёнными. Подтверждение фиксируется в истории | При актуальном нуле запрос не создаётся. Без подтверждения новой записи нет; при подтверждённой отправке сохранены продавец и время. | [BG-01](#bg-01), [BG-05](#bg-05), [RULE-03](#rule-03), [RULE-21](#rule-21), [RULE-23](#rule-23), [FR-32](#fr-32) |
| FR-32 | <a id="fr-32"></a>Перед каждой новой отправкой обычного или альтернативного запроса система получает из существующей системы текущий остаток выбранного магазина и точного варианта. Успешный ответ со значением используется для этой попытки; ошибка, отсутствие значения или неподтверждённая актуальность переводят отправку в ветку предупреждения [FR-31](#fr-31). После потерянного ответа о создании запроса повтор обрабатывается как исходное действие по [FR-11](#fr-11) / [FR-16](#fr-16) | Для каждой новой отправки выполнено отдельное обновление; старое значение из карточки не заменяет его. Полученный ноль блокирует запрос, положительное значение допускает отправку. При неудаче показано предупреждение и требуется отдельное подтверждение. Учётное обновление не снимает предупреждение о прошлом «Не найдено» и не гарантирует выдачу. | [BG-01](#bg-01), [BG-05](#bg-05), [RULE-03](#rule-03), [RULE-21](#rule-21), [RULE-23](#rule-23), [FR-11](#fr-11), [FR-16](#fr-16) |
